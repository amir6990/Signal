# دریافت داده طلا و ارز

```bash
python scripts/fetch_gold_fx.py --probe                    # اول این را اجرا کنید
python scripts/fetch_gold_fx.py --show                     # دریافت و نمایش
python scripts/fetch_gold_fx.py --write --append-history   # نوشتن در فایل‌ها
python scripts/fetch_gold_fx.py --manual my.json --write   # از فایل دستی
python scripts/fetch_gold_fx.py --history                  # پر کردن کل تاریخچه
python scripts/refresh_all.py --fetch-gold-fx              # به‌عنوان بخشی از زنجیره
```

## چرا اینجا فرق دارد

برای بورس یک API مرجع وجود دارد: `cdn.tsetmc.com`. برای **دلار آزاد و طلای
داخلی ایران هیچ API عمومی، مستند و پایداری وجود ندارد.** آنچه هست یا
غیررسمی است، یا کلید می‌خواهد، یا هر چند وقت ساختارش عوض می‌شود.

پس به‌جای یک منبع، معماری چندمنبعی با تشخیص خودکار ساخته شده.

| منبع | کمیت‌ها | کلید | ساختار |
|---|---|---|---|
| **فایل دستی** | همه ۱۳ کمیت | — | ✅ تأییدشده |
| **Nobitex** | تتر (ریال) + تاریخچه OHLC | — | ✅ از مستندات رسمی |
| **tgju.org** | دلار، نیمایی، یورو، درهم، اونس، نقره، سکه، گرم، حباب + تاریخچه | — | ✅ از کد عمومی کارکرده |
| BrsApi.ir | ارز، طلا، سکه | ✅ لازم | ❌ حدسی |
| gold-api.com | اونس طلا و نقره | — | ❌ حدسی |
| Stooq | اونس طلا و نقره | — | ❌ حدسی |
| open.er-api.com | نرخ برابری جهانی | — | ❌ حدسی |

**«تأییدشده» یعنی ساختار درخواست و پاسخ راستی‌آزمایی شده — نه اینکه من آن را
صدا زده باشم.** شبکه محیط ساخت این پروژه به هر دو میزبان بسته است
(`gateway answered 403 to CONNECT`). راستی‌آزمایی از راه خواندن کد عمومیِ
کارکرده انجام شده، نه حدس زدن شکل رایج endpointها.

به همین دلیل `--probe` وجود دارد: تنها چیزی که ثابت می‌کند این‌ها **امروز از
ماشین شما** کار می‌کنند، اجرای آن است.

### ساختار تأییدشده Nobitex

```
GET  /market/stats?srcCurrency=usdt&dstCurrency=rls      قیمت لحظه‌ای
GET  /market/udf/history?symbol=USDTIRT&resolution=D&from=<epoch>&to=<epoch>
GET  /v3/orderbook/USDTIRT                                عمق بازار
میزبان‌ها: api.nobitex.ir ، apiv2.nobitex.ir     (هم GET و هم POST کار می‌کند)
```

پاسخ تاریخچه: `{"s":"ok","t":[epoch...],"o":[],"h":[],"l":[],"c":[],"v":[]}`
با زمان بر حسب **ثانیه**.

> ⚠️ **تله واحد — مهم‌ترین نکته این صفحه.** در `/market/stats` پارامتر
> `dstCurrency=rls` یعنی **ریال** و `irt` یعنی **تومان**. ولی در
> `/market/udf/history` نماد `USDTIRT` قیمت را به **تومان** می‌دهد. نمونه
> رسمی خود نوبیتکس این را تأیید می‌کند: `BTCIRT` در تیر ۱۳۹۸ حدود
> ۱۴۶٬۲۷۲٬۵۰۰ است که با بیت‌کوین ۱۱٬۰۰۰ دلاری فقط به تومان جور درمی‌آید.
> پس این پکیج تاریخچه را **×۱۰** می‌کند تا همه‌جا ریال باشد
> (`HISTORY_SYMBOLS` در `providers/nobitex.py`). اگر روزی این ضریب را
> عوض کردید، حباب سکه و پریمیوم تتر هم غلط می‌شوند.

### ساختار تأییدشده tgju

```
لحظه‌ای:  https://call{1..5}.tgju.org/ajax.json           ۵ میرور
          {"current": {"<نماد>": {"p": قیمت, "h":.., "l":.., "t":..}}}

تاریخچه:  https://api.tgju.org/v1/market/indicator/summary-table-data/{نماد}
          میرور: https://api.accessban.com/... (همان مسیر)
          {"data": [[باز, کمترین, بیشترین, بسته, تغییرHTML, درصدHTML,
                     تاریخ‌شمسی, تاریخ‌میلادی], ...]}
```

نمادهای استفاده‌شده:

| نماد tgju | معنا |
|---|---|
| `price_dollar_rl` | دلار آزاد |
| `nima_sell_usd` | دلار نیمایی |
| `price_eur` / `price_aed` | یورو / درهم |
| `ons` / `silver_999` | اونس طلا / نقره جهانی |
| `geram18` | طلای ۱۸ عیار |
| `sekee` / `nim` / `rob` | سکه تمام / نیم / ربع |
| `coin_blubber` / `nim_blubber` / `rob_blubber` | حباب همان سکه‌ها |

دو نکته که موقع تجزیه اهمیت دارند: ستون‌های تغییر و درصد **داخلشان HTML
دارند** و باید پاک شوند؛ و ستون تاریخ **میلادی** (ایندکس ۷) استفاده می‌شود نه
شمسی (ایندکس ۶)، چون تبدیل دوباره‌اش خطا اضافه می‌کند.

## `--probe` — اولین کاری که باید بکنید

هر منبع را واقعاً صدا می‌زند و می‌گوید کدام از **ماشین شما** کار می‌کند:

```
کلید       منبع                       وضعیت      نتیجه
manual     فایل دستی (JSON محلی)      ✔ کار کرد  13 کمیت
nobitex    Nobitex (api.nobitex.ir)   ✔ کار کرد  1 کمیت  تتر=969,500
tgju       tgju.org (غیررسمی)         ✘          پاسخ گرفته شد ولی کلید current نبود

پوشش هر کمیت با منابع کارکرده:
  ✔ تتر (ریال)          nobitex، manual
  ✘ دلار آزاد (ریال)    هیچ منبعی
```

پیام خطا عمداً تفکیک‌شده است، چون درمان این دو فرق دارد:

| پیام | معنا | راه‌حل |
|---|---|---|
| `<urlopen error ...>` | شبکه بسته یا سایت در دسترس نیست | فیلترشکن، یا منبع دیگر |
| `کلید current نبود` | پاسخ آمد ولی **ساختار عوض شده** | نگاشت `KEYS` را در `providers/tgju.py` اصلاح کنید |
| `کلید API تنظیم نشده` | منبع نیازمند کلید است | کلید را در `scripts/market_sources.json` بگذارید |

## دو لایه محافظت در برابر داده غلط

### لایه ۱ — بازه سلامت مطلق

خطای فاحش را می‌گیرد: دلار ۹۵٬۰۰۰ (تومان به‌جای ریال) رد می‌شود چون خارج از
بازه ۱۰۰٬۰۰۰ تا ۱۰۰٬۰۰۰٬۰۰۰ است.

### لایه ۲ — سازگاری متقابل (مهم‌تر)

بازه مطلق در اقتصاد تورمی کهنه می‌شود و خطای ۱۰ برابری سکه را نمی‌گیرد —
چون هر دو عدد در بازه‌اند. اما **نسبت‌ها پایدارند**:

| آزمون | بازه مجاز |
|---|---|
| سکه ÷ ارزش ذاتی (از اونس و دلار) | ۰٫۸۰ تا ۲٫۵۰ |
| گرم ۱۸ عیار ÷ ارزش خام فلز | ۰٫۸۵ تا ۱٫۶۰ |
| پریمیوم تتر | ‎−۵٪ تا ‎+۲۵٪ |
| نیم سکه ÷ (سکه÷۲) | ۰٫۹۰ تا ۱٫۳۰ |
| ربع سکه ÷ (سکه÷۴) | ۰٫۹۰ تا ۱٫۷۰ |
| یورو ÷ دلار | ۰٫۹۰ تا ۱٫۴۰ |
| درهم ÷ دلار | ۰٫۲۲ تا ۰٫۳۳ |
| دلار آزاد ÷ نیمایی | باید > ۰٫۹۵ |

سکه با واحد غلط، **سه ناسازگاری همزمان** تولید می‌کند. و چون آزمون نسبتی
است، تورم ۵ برابری هیچ هشدار کاذبی نمی‌دهد — این را تست خودکار بررسی می‌کند.

⚠️ باند مسکوکات کوچک عمداً گشاد است: در بازار ایران نیم سکه و ربع سکه
**ساختاراً حباب بیشتری** از سکه تمام دارند. باند اولیه من (۰٫۸۰–۱٫۲۵) روی
داده سالم هشدار کاذب می‌داد و اصلاح شد.

**مقدار ناسازگار نوشته نمی‌شود.** با `--force` می‌توانید مجبورش کنید، ولی
پیش‌فرض این است که عدد مشکوک وارد فایل نشود.

## `--history` — پر کردن کل تاریخچه

`--append-history` یک ردیف برای امروز می‌افزاید. `--history` کارِ دیگری
می‌کند: **کل سری را از منبع می‌گیرد و جای داده نمایشی می‌نشاند.**

```bash
python scripts/fetch_gold_fx.py --history
python scripts/recalc.py Gold_Analysis.xlsx FX_Analysis.xlsx   # اجباری
```

| شیت | سری | منبع | سنجه ارزش‌گذاری (ستون P) |
|---|---|---|---|
| `Gold_History` | سکه تمام | tgju `sekee` | حباب سکه |
| `Hist_Gram18` | طلای ۱۸ عیار | tgju `geram18` | پریمیوم نسبت به فلز جهانی |
| `Hist_Ons` | اونس جهانی | tgju `ons` | — |
| `FX_History` | دلار آزاد | tgju `price_dollar_rl` | شکاف با نیمایی |
| `Hist_USDT` | تتر | Nobitex `USDTIRT` | پریمیوم نسبت به دلار آزاد |
| `Hist_Nima` | دلار نیمایی | tgju `nima_sell_usd` | — |

### چرا سنجه ارزش‌گذاری در پایتون ساخته می‌شود، نه در اکسل

```
حباب سکه    = قیمت سکه ÷ (۷٫۳۱۹۷ گرم × اونس ÷ ۳۱٫۱۰۳۴۷۶۸ × دلار) − ۱
پریمیوم گرم = طلای ۱۸ عیار ÷ (۰٫۷۵۰ × اونس ÷ ۳۱٫۱۰۳۴۷۶۸ × دلار) − ۱
شکاف نیمایی = دلار آزاد ÷ دلار نیمایی − ۱
پریمیوم تتر = تتر ÷ دلار آزاد − ۱
```

هر کدام به **چند سری با تاریخ‌های ناهمسان** نیاز دارد. بازار طلای داخلی و
بازار جهانی در روزهای یکسانی تعطیل نیستند؛ نوبیتکس ۲۴ ساعته است ولی صرافی
نیست. در پایتون این یک join روی مجموعه تاریخ‌های مشترک است. در اکسل به
زنجیره‌ای از `INDEX/MATCH` تبدیل می‌شود که با اولین تعطیلی نامتقارن، بی‌صدا
عدد غلط می‌دهد.

**اما صدک تاریخی همان سنجه در اکسل حساب می‌شود** (ستون Q، با
`PERCENTRANK`) تا با تغییر داده، خودش به‌روز بماند.

دو محافظ در این مسیر:

- **دامنه معقول برای هر سنجه** (`VAL_SANITY` در `market_data/history.py`).
  حباب سکه بیرون از بازه −۳۰٪ تا +۱۵۰٪ نوشته نمی‌شود. این دقیقاً همان تله
  ریال/تومان را می‌گیرد: سکه‌ای که به تومان خوانده شده حباب حدود −۸۸٪ می‌دهد
  و رد می‌شود.
- **روزی که یکی از نهاده‌هایش را ندارد، سنجه نمی‌گیرد** — سلول خالی می‌ماند.
  صفر گذاشتن یعنی «حباب صفر» که یک ادعای غلط است، نه یک مقدار نامعلوم.

اگر یک سری دریافت نشود، شیتش **دست‌نخورده** می‌ماند و اسکریپت صریحاً
می‌گوید کدام. پاک کردن داده قبلی و جا گذاشتن شیت خالی بدتر از نگه داشتن
داده قدیمی است.

## سیگنال طلا، سکه، دلار و تتر

شیت `Asset_Signals` در هر دو فایل، برای هر دارایی یک ردیف دارد و همان پنج
برچسب سهام را می‌دهد (خرید قوی / خرید / نگهداری / فروش / فروش قوی).

چهار زیرنمره، هرکدام −۱۰ تا +۱۰:

| زیرنمره | مبنا | وزن پیش‌فرض |
|---|---|---|
| T روند | قیمت نسبت به سه میانگین متحرک | ۳۵٪ (`AW_TREND`) |
| M مومنتوم | بازده ۵ و ۲۰ و ۶۰ روزه | ۲۵٪ (`AW_MOM`) |
| V نوسان | نوسان جاری نسبت به میانه تاریخی | ۱۵٪ (`AW_VOL`) |
| P ارزش‌گذاری | **صدک تاریخی** حباب یا پریمیوم | ۲۵٪ (`AW_VAL`) |

وزن‌ها در بخش ۹ شیت `Settings` قابل تغییرند.

بُعد چهارم چیزی است که در سهام معادل ندارد و مهم‌ترین بخش این شیت است:
**حباب ۱۸٪ به‌تنهایی هیچ معنایی ندارد.** آنچه معنا دارد این است که ۱۸٪ در
توزیع دو سال گذشته کجا می‌ایستد. اگر صدکش ۹۰٪ باشد یعنی گران‌ترین حالت
تاریخی‌اش؛ اگر ۱۰٪ باشد یعنی ارزان. امتیاز P از همین صدک می‌آید، نه از خود
عدد حباب.

> ⚠️ اگر ستون سنجه پر نشده باشد، **وزن ارزش‌گذاری از مخرج هم حذف می‌شود**.
> در غیر این صورت نبودِ داده امتیاز را ۲۵٪ به سمت صفر رقیق می‌کرد و یک روند
> قوی را بی‌دلیل ضعیف نشان می‌داد. برای همین اونس جهانی (که سنجه ندارد) با
> مخرج ۰٫۷۵ حساب می‌شود نه ۱٫۰۰.

> ⚠️ **هیچ‌کدام از این آستانه‌ها و وزن‌ها بک‌تست نشده‌اند.** برای آزمودنشان:
> `python -m timeframe backtest --csv <سری>.csv --name <دارایی>`

**همه قیمت‌ها به ریال‌اند، نه تومان.** رایج‌ترین خطای این حوزه ضریب ۱۰ است.

## محدودیت‌ها

- **هیچ منبعی از محیط ساخت این پروژه صدا زده نشده** — شبکه بسته است. برای
  tgju و Nobitex ساختار از کد عمومی کارکرده و مستندات رسمی استخراج شده؛
  برای چهار منبع دیگر حتی این هم نیست. با `--probe` خودتان بسنجید.
- منابع غیررسمی ممکن است بدون اطلاع تغییر کنند. پیام خطا به شما می‌گوید کدام
  فایل را باید اصلاح کنید.
- `dxy` منبع خودکار قابل‌اتکایی ندارد — احتمالاً دستی بماند. (برای
  `usd_irr_nima` نماد `nima_sell_usd` در tgju وجود دارد؛ پیش‌تر گفته بودم
  ندارد که درست نبود.)
- سنجه ارزش‌گذاری فقط برای روزهایی ساخته می‌شود که **همه** نهاده‌هایش موجودند.
  اگر tgju اونس را ندهد، حباب سکه هم ساخته نمی‌شود — هرچند قیمت سکه آمده باشد.
- این snapshot است، نه استریم. زمان‌بندی خودکار با `cron` (لینوکس) یا Task
  Scheduler (ویندوز) قابل افزودن است.
