# ساختار فایل‌ها

پنج فایل مستقل به‌جای یک فایل یکپارچه.

```bash
python src/build_all.py              # ساخت هر پنج فایل
python src/build_all.py --only gold  # فقط یکی
python src/build_all.py --list       # فهرست
python scripts/refresh_all.py        # به‌روزرسانی کامل با ترتیب درست
```

| فایل | شیت‌ها | حجم | نقش |
|---|---|---|---|
| `Stocks_Signals.xlsx` | ۱۱ | ~۱٫۲MB | سیگنال سهام بورس و فرابورس |
| `Options_Signals.xlsx` | ۵ | ~۷۰KB | اختیار معامله |
| `Time_Analysis.xlsx` | ۶ | ~۵۰KB | چرخه‌ها، لایه کلان، پیش‌بینی |
| `Gold_Analysis.xlsx` | ۶ | ~۳۲۰KB | طلا و سکه |
| `FX_Analysis.xlsx` | ۶ | ~۳۲۰KB | دلار و تتر |

فایل سهام سنگین‌ترین است چون تاریخچه روزانه را نگه می‌دارد — برای میانگین
متحرک ۲۰۰ روزه گریزی از آن نیست. بقیه فایل‌ها آن را ندارند و سبک‌اند.

---

## قانون معماری: هیچ ارجاع بین‌فایلی اکسل وجود ندارد

فرمول `='[1]Sheet'!A1` سه مشکل دارد:

1. وقتی فایل مبدأ باز نباشد فقط **مقدار کش‌شده** را نشان می‌دهد.
2. مسیر فایل را **مطلق** ذخیره می‌کند — با جابه‌جایی پوشه می‌شکند.
3. با بازنویسی فایل توسط `openpyxl` **کاملاً از بین می‌رود**.

به‌جای آن، هر فایل خودکفاست و پایتون پل بین آن‌هاست:

```
Stocks_Signals.xlsx ──┬─→ Time_Link   ←── timeframe export   (امتیاز زمانی)
                      └─→ Underlying  ←── link_workbooks.py  (قیمت و امتیاز سهم پایه)
```

هر پل تاریخ به‌روزرسانی و منبع را هم می‌نویسد، پس همیشه معلوم است داده چقدر
کهنه است. تست خودکار بررسی می‌کند که هیچ فایلی نه به شیت غایب ارجاع دهد و
نه به فایل دیگر.

---

## ترتیب به‌روزرسانی — و دامی که در آن می‌افتید

`openpyxl` فرمول‌ها را به‌صورت متن می‌نویسد و **مقدار محاسبه‌شده را ذخیره
نمی‌کند**. پس هر بار که یک اسکریپت پایتون فایلی را بازنویسی می‌کند، مقادیر
کش‌شده پاک می‌شوند و اسکریپت پل بعدی چیزی برای خواندن ندارد.

ترتیب درست:

| گام | کار | چرا |
|---|---|---|
| ۱ | `tse_updater.py` → فایل سهام | دریافت داده از API |
| ۲ | بازمحاسبه فایل سهام | تولید مقادیر |
| ۳ | `timeframe export` → فایل زمانی + `Time_Link` | تحلیل چرخه |
| ۴ | **بازمحاسبه دوباره فایل سهام** | گام ۳ فایل را بازنویسی کرده |
| ۵ | `link_workbooks.py` → فایل آپشن | انتقال سهم پایه |
| ۶ | بازمحاسبه فایل آپشن و زمانی | تولید مقادیر نهایی |

`scripts/refresh_all.py` همه این‌ها را با ترتیب درست اجرا می‌کند:

```bash
python scripts/refresh_all.py            # بدون فراخوانی API
python scripts/refresh_all.py --fetch    # با دریافت داده از tsetmc
python scripts/refresh_all.py --skip-recalc   # اگر LibreOffice ندارید
```

بدون LibreOffice، گام‌های بازمحاسبه را باید دستی انجام دهید: فایل را در اکسل
باز کنید، `Ctrl+Alt+F9` بزنید و ذخیره کنید.

## Gold_Analysis.xlsx

`Gold_Input` ← اونس، نرخ ارز، قیمت بازار سکه.
`Coin_Bubble` ← ارزش ذاتی و حباب چهار مسکوک + طلای ۱۸ عیار.

```
ارزش ذاتی = طلای خالص (گرم) × (اونس ÷ ۳۱٫۱۰۳۴۷۶۸) × نرخ ارز
حباب       = قیمت بازار ÷ ارزش ذاتی − ۱
```

سکه تمام: ۸٫۱۳۳ گرم عیار ۹۰۰ ← ۷٫۳۱۹۷ گرم طلای خالص.

**تفکیک بازده به سه محرک** — مهم‌ترین بخش این فایل. با اعداد نمونه:

| جزء | مقدار |
|---|---|
| بازده کل ریالی سکه | ‎+۸۰٫۰٪ |
| سهم طلای جهانی | ‎+۳۰٫۸٪ |
| سهم نرخ ارز | ‎+۵۸٫۳٪ |
| سهم تغییر حباب | ‎−۱۳٫۱٪ |
| **کنترل صحت** | **‎+۸۰٫۰٪ ✔** |

سلول کنترل باید دقیقاً با بازده کل یکی باشد؛ اگر نبود، یکی از ورودی‌ها
ناسازگار است. در این مثال بزرگ‌ترین جزء **نرخ ارز** است — یعنی این یک موقعیت
ارزی است که لباس طلا پوشیده.

حباب یک سنجه ارزش‌گذاری است، نه سیگنال زمان‌بندی: می‌تواند ماه‌ها بالا بماند.

## FX_Analysis.xlsx

`FX_Input` ← دلار آزاد، نیمایی، تتر، یورو، درهم، اونس، سکه.
`Spreads` ← شکاف‌ها، پریمیوم و نرخ ضمنی از دو مسیر مستقل.

با اعداد نمونه:

| سنجه | مقدار |
|---|---|
| شکاف آزاد و نیمایی | ‎۳۱٫۹٪ |
| پریمیوم تتر | ‎۱٫۸۹٪ |
| نرخ ضمنی از تتر | ۹۶۷٬۷۱۰ |
| نرخ ضمنی از سکه | ۹۵۳٬۲۲۹ |
| واگرایی دو مسیر | ‎۰٫۳۴٪ |

**تتر و دلار آزاد هر دو دلارند.** اختلافشان نرخ متفاوت نیست — هزینه است:
کارمزد صرافی، ریسک انتقال، تقاضای لحظه‌ای نقدشوندگی. پریمیوم پایدارِ بالای
چند درصد معمولاً محدودیت دسترسی به اسکناس یا فشار خروج سرمایه را نشان می‌دهد.

واگرایی زیاد بین نرخ ضمنی از تتر و از سکه یعنی یکی از دو بازار هنوز تعدیل
نشده — یا داده ورودی کهنه است.

⚠️ نرخ ضمنی از سکه به **فرض حباب** بسیار حساس است. آن را در `FX_Input` وارد
می‌کنید و اگر اشتباه باشد، نرخ ضمنی هم اشتباه است.

**این فایل نرخ ارز را پیش‌بینی نمی‌کند.** جهش ارزی در ایران پله‌ای و وابسته
به تصمیم سیاستی است؛ دوره‌ای‌کردن آن خطای روش‌شناختی است.

## دو باگی که در ساخت این تفکیک پیدا و رفع شد

**۱. شمارنده ردیف روی هدر متنی.** فرمول `=IF($A5<>"",$G4+1,"")` در ردیف اول
داده به سلول هدر (متن) ارجاع می‌داد → `#VALUE!` که به ۴۰۱۹ سلول سرایت کرد.
اصلاح: `ISNUMBER($G4)` به‌جای مقایسه مستقیم.

**۲. ردیف‌های خالی ظرفیت.** `$C5/$C4-1` روی ردیف خالی → `#DIV/0!` در ۵۷۱۳
سلول. اصلاح: گارد صریح روی `ISNUMBER` و `<>0`.

هر دو با بازمحاسبه LibreOffice پیدا شدند، نه با بازرسی چشمی. اکنون هر پنج
فایل با **صفر خطا** بازمحاسبه می‌شوند:

| فایل | فرمول | خطا |
|---|---|---|
| Stocks_Signals | ۴۸٬۵۶۲ | ۰ |
| Gold_Analysis | ۱۵٬۳۶۰ | ۰ |
| FX_Analysis | ۱۵٬۳۴۴ | ۰ |
| Options_Signals | ۲٬۱۶۰ | ۰ |
| Time_Analysis | ۸۴۲ | ۰ |
| **جمع** | **۸۲٬۲۶۸** | **۰** |

**۳. باگ سوم — در ابزار خودم.** نسخه اول `scripts/recalc.py` از فراخوانی
ماکرو استفاده می‌کرد، «موفق» گزارش می‌داد ولی هیچ مقداری نمی‌نوشت. با بررسی
مقادیر کش‌شده کشف شد و با روش `convert-to` جایگزین شد که راستی‌آزمایی شده است.
